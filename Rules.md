# Rules.md — правила роботи AI-асистента над «Трекером витрат»

Цей файл — контракт між розробником і AI-асистентом (Claude, Copilot, Gemini тощо). Перед генерацією
коду асистент зобов’язаний прочитати його повністю. Якщо запит суперечить правилам нижче — спершу
повідомити про конфлікт, а не мовчки порушувати правило.

## 1. Про проєкт

Нативний Android-застосунок для обліку особистих витрат: додавання транзакцій, баланс із місячним
бюджетом, аналітика за категоріями, історія, курси валют НБУ (офлайн-кеш), щоденне нагадування о 20:00,
PIN-захист. Мова інтерфейсу — **українська**; мова коду, імен і комітів — **англійська**;
коментарі та документація — **українською**.

## 2. Стек (не змінювати без погодження)

| Область | Технологія |
|---|---|
| Мова / UI | Kotlin 2.0, Jetpack Compose, Material 3 |
| Навігація | Navigation Compose 2.8+ з типобезпечними `@Serializable`-маршрутами |
| Дані | Room (+ `Flow`), KSP; секрети — `EncryptedSharedPreferences` |
| Мережа | Retrofit + kotlinx.serialization, API НБУ |
| Стан | `ViewModel` + `StateFlow` (+ `combine`/`stateIn`) |
| Фон | WorkManager (`PeriodicWorkRequest`), `BOOT_COMPLETED`-ресівер |
| Тести | JUnit4, MockK, kotlinx-coroutines-test, Turbine |
| DI | Ручний (`AppContainer` + `ViewModelFactories`), без Hilt/Dagger |

minSdk 26, targetSdk/compileSdk 35. Нові залежності додавати лише через `gradle/libs.versions.toml`.

## 3. Архітектура та правила залежностей

```
ui  ──►  domain  ◄──  data
```

* `domain` — чистий Kotlin: моделі, правила, інтерфейси репозиторіїв. **Жодних імпортів `android.*`,
  `androidx.*` (крім `kotlinx.*`), Room, Retrofit.** Саме тому його можна тестувати без емулятора.
* `data` реалізує інтерфейси домену (Room, Retrofit, `EncryptedSharedPreferences`). Логіка рішень
  (offline-first, лічильники спроб PIN, мапінг DTO) пишеться як чистий Kotlin над вузькими інтерфейсами
  (`RatesLocalDataSource`, `SecureKeyValueStore`…), а Android-реалізації лишаються тонкими.
* `ui` = `Route`-composable (бере `ViewModel`, збирає стан) + stateless `Screen`-composable
  (приймає `state` і колбеки, має `@Preview`). `ViewModel` не знає про `Context` і Compose.
* Односпрямований потік даних: `UiState` (immutable `data class`) вниз, події (лямбди) вгору.
  Одноразові події (навігація, снекбар) — `Channel` → `Flow`, не прапорці в стані.
* Єдине джерело правди — база даних. UI ніколи не читає мережу напряму.

## 4. Гроші та час

* Суми — **`Long` у мінімальних одиницях** (копійки/центи), ніколи `Float`/`Double`.
  Колонка `expenses.amount` зберігає саме мінімальні одиниці.
* Введення користувача проходить через `AmountParser` (крапка/кома, ≤ 2 знаки, > 0, ≤ 999 999 999,99).
* Конвертація — лише через `RateTable` (`BigDecimal`, `RoundingMode.HALF_UP`), курс завжди > 0.
  Відсутній курс — це `null`/позначка «немає курсу», а не `0` чи виняток у UI.
* Час — `Long` epoch-мс у UTC; межі місяця рахуються через `TimeRange` у зоні користувача.
  `Clock` передається ззовні (щоб тести були детермінованими).

## 5. UI та дизайн-система

* Material 3 (`MaterialTheme.colorScheme`, `typography`). **Заборонено** хардкодити кольори в
  composable — лише ролі теми або `categoryColors(category)`.
* Мінімальна зона дотику 48 dp; кожна іконка-кнопка має `contentDescription`.
* Світла й темна теми обов’язкові; динамічні кольори вимкнені, щоб палітра категорій лишалась стабільною.
* Числове поле — `KeyboardType.Decimal`; помилки валідації показуються після першої спроби збереження.
* Рядки UI українською; довгі списки — `LazyColumn` зі стабільними `key`.

## 6. Навігація

* Маршрути — `@Serializable` `object`/`data class` у `ui/navigation/Routes.kt`; рядкових роутів немає.
* Аргументи передаються типізовано (`ExpenseHistoryRoute(category: String?)`), читаються через `toRoute<T>()`.
* Нижня панель — лише верхньорівневі напрямки (`Огляд`, `Аналітика`); перехід між ними —
  `launchSingleTop` + `restoreState` + `popUpTo(startDestination) { saveState = true }`.
* Deep link-и оголошуються на маршруті (`navDeepLink<T>`), а не розбираються вручну в `Activity`.

## 7. Дані та безпека

* Схема Room версіонується, `exportSchema = true`; зміна схеми = нова `Migration` (без `fallbackToDestructiveMigration`).
* PIN **ніколи** не зберігається відкритим текстом: лише PBKDF2-хеш із сіллю у `EncryptedSharedPreferences`.
  Невдалі спроби лімітуються (тимчасове блокування).
* `allowBackup="false"`; ні PIN, ні суми не потрапляють у логи.
* Мережа лише HTTPS; відповіді API валідуються (курс > 0, відомий код валюти) перед записом у БД.
* Дозволи: `POST_NOTIFICATIONS` (запит у рантаймі, Android 13+), `RECEIVE_BOOT_COMPLETED`, `INTERNET`.

## 8. Тестування (обов’язково)

* Будь-яка нова бізнес-логіка в `domain`/`data` постачається з unit-тестами (JUnit4 + MockK).
* Обов’язкові граничні випадки: нуль, від’ємні, надто великі та дробові суми; нульовий/від’ємний/відсутній
  курс; відсутність інтернету; порожня БД; межі місяця й перехід на літній час.
* Корутини тестуються через `runTest` + `MainDispatcherRule`; потоки — через Turbine.
* Тест не повинен залежати від поточної дати чи мережі — лише `Clock.fixed` і фейки/моки.
* Перед завершенням завдання: `./gradlew testDebugUnitTest lintDebug`.

## 9. Стиль коду

* Офіційний Kotlin code style; `val` замість `var`; `data class` для станів; `sealed interface` для подій і результатів.
* Публічні функції домену документуються KDoc українською з описом граничних випадків.
* Без `!!`, без `GlobalScope`, без `runCatching`, що ковтає `CancellationException`.
* Один composable-файл — один екран (+ його приватні дрібні компоненти).

## 10. Чого AI робити не повинен

* Не додавати залежності, дозволи, аналітику чи мережеві виклики, яких немає в завданні.
* Не змінювати публічні контракти домену без оновлення тестів.
* Не вигадувати API бібліотек: якщо не впевнений у сигнатурі — сказати про це й вказати, що саме перевірити.
* Не видаляти й не послаблювати тести, щоб «позеленіти».
* Не записувати секрети (ключі, PIN, токени) у код, логи або тестові фікстури.
